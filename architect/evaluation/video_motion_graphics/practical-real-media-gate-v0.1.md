## Required motion problems

### P1 — Attention migration

Create a truthful conceptual visualization of attention moving from an older project toward a newer project.

Must:
- communicate directional migration clearly;
- remain conceptual, not measured;
- avoid fabricated y-axis, percentages, market-share values or quantitative slopes;
- integrate with the speaker/captions without layer competition.

### P2 — Investment lifecycle

Create one coherent visual system for:
`entry/purchase -> hold -> exit/sale`.

Must:
- make sequence and relationship obvious;
- animate semantic progression rather than merely reveal three labels;
- preserve enough hold time to comprehend;
- avoid mechanical constant-speed UI movement.

### P3 — CTA resolution

Resolve motion back to the speaker and CTA without leaving a visually separate “presentation slide” feeling.

Must:
- preserve the human speaker as the final authority;
- keep CTA readable;
- avoid unnecessary full-frame complexity.

## Renderer gate

The chosen direction must be mapped to runtime capability before execution.

If the direction requires:
- editable motion curves/easing;
- vector path animation;
- masks/mattes;
- tracked compositing;
- reusable layered assets;

then the executor must provide those capabilities or the candidate must simplify the mechanism explicitly.

FFmpeg primitive `drawtext/drawbox` alone does not satisfy the intended professional motion-design execution surface for this practical gate.
