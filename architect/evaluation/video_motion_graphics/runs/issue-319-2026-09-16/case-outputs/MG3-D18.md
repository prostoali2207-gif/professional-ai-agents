# MG3-D18 — Decision: final motion system for the short explanation

## Decision

The proposed treatment is rejected as a system. I am approving a three-layer
system: **subject/diagram → captions → one bounded scene device.** Particles,
glow, icon loops and the animated counters come out. Parallax and camera
movement collapse into at most one authored move, and only if it carries a
scene job.

Assumptions I am proceeding on: wording is approved and the caption layer is
effectively locked for this revision; the diagram is the approved explanatory
mechanism; there is no approved dataset behind the counters; the piece is a
short mobile-first explanation.

## Diagnosis

This is not six small questions, it is one composed-system question. Each
effect being individually polished is exactly the failure mode — polish per
element does not survive combined attention load. Right now three layers
(diagram, captions, ambient effects) all move at once and none of them owns
the eye. The repair rule is to remove or delay a layer before adding emphasis,
not to re-time six competing layers against each other.

Running the motion information-gain test (`job → represented change → viewer
inference → timing/hold → removal criterion`) over the proposal:

- **Diagram animation** — passes. It is the only element whose motion carries
  the explanation itself: state change, sequence or transfer. It is the motion
  carrier of the piece.
- **Captions** — pass, as timed communication. Emphasis only where an accent
  has a semantic or attention function. No accent added for energy.
- **Particles** — fail. No represented change, no viewer inference, no removal
  criterion. Ambient texture competing with the diagram.
- **Glow** — fail. Applied as a quality signal, not a hierarchy device. Also
  the classic attempt to hide a generic visual system under an effect.
- **Icon loops** — fail. Perpetual motion with no end state trains the eye to
  a region that carries no information, and it never stops stealing attention.
- **Counters** — fail on two counts. No information gain over a held value, and
  more seriously, an animating count-up reads as measured magnitude. Without
  approved data behind it that is an integrity problem, not a taste problem.
- **Parallax / camera** — conditionally eligible, but not both. One of them, as
  a single authored move on a scene or reveal, with a defined settle. Two
  simultaneous depth devices on a short piece is unjustified complexity.

"Polished individually," "dynamic" and "the renderer can do it" are not
justifications under the motion gate.

## Actions

1. Rewrite the treatment to the three-layer system above; name the diagram as
   the sole motion carrier.
2. Re-test the diagram mechanism before authoring: persistent object changing
   state, object moving through states, relationship change, transfer, or
   accumulation — do not default to numbered cards. Pick the one that best
   preserves identity and causality.
3. Route the counters upstream. If the numbers are wanted, I need approved
   values and a source; otherwise they stay out or become a held static value
   with no implied rate.
4. Confirm the structural edit is locked before any of this is fully authored.
   No expensive timing work on unstable structure.
5. Produce styleframes (opening, peak explanatory, resolved) plus one short
   animated prototype showing the real motion language, including the single
   camera/parallax move. Gate there. If it already reads as generic
   presentation UI, repair the system — composition, type, motif, spacing —
   not the effect stack.
6. Build the overlay ledger (`overlay text → approved beat → time range →
   owner`) before render.
7. Review typography as designed form, not by adding outline, shadow or a
   fashionable face.
