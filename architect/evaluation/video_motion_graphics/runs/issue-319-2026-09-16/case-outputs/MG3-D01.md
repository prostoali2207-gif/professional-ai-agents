## Diagnosis

This is not a polish problem and not a technical problem. Classified: `CRAFT_FAIL` — primary failure `GENERIC_VISUAL_SYSTEM` (MG3-01), with contributing `GENERIC_TEMPLATE_TYPOGRAPHY` (MG3-06) and probable silent authoring downgrade (MG3-14).

Assumptions I am proceeding on: the render was observed at representative phone size (otherwise the correct state is `TECHNICAL_PASS_CRAFT_NOT_OBSERVED`, not a diagnosis); the structural edit is locked and the narration/beat map is approved; overlay wording is approved and some caption/title layers may be locked.

Observable causes, not "it doesn't feel premium":

1. **Single container motif.** Rounded app-card panels in every scene means one container is carrying all content types — statements, comparisons, process, proof. The panel is doing the compositional work that composition, scale and negative space should do. The piece therefore has no graphic language of its own, only a component library.
2. **Flat hierarchy.** Equal-weight labels mean the viewer is not told where to look first. Under MG3-01/MG-03 the required order is subject/proof, then graphic, then captions, then labels/branding. Equal weight collapses that into simultaneous reading, which on a vertical phone frame reads as a dashboard.
3. **Safe centered spacing.** Centering everything removes proportion decisions. There is no grid tension, no asymmetry, no scale contrast, so no scene has a visual argument. Alignment has been mistaken for composition.
4. **Cards as default explanation form.** Per MG3-08, a card sequence almost certainly replaced a better mechanism: one persistent object changing state, a transfer/migration, a relationship shifting, or accumulation. Cards preserve none of identity, causality or continuity — each cut destroys and rebuilds the subject, which is why scene-to-scene coherence is absent.
5. **Likely convenience-driven surface.** Rounded panels plus centered text plus uniform labels is what is cheapest to implement in CSS/component terms. That is the MG3-14 failure mode: intended craft quietly collapsed into what the renderer makes easy.

## Repair strategy

I will not repair this with color, gradients, shadows, outlines, a fashionable typeface or added effects. That hides genericity and usually makes the craft QC worse.

Re-enter the workflow at the styleframe/prototype gate (MG3-13), not at render:

1. **Lock map first.** Confirm which caption/title/brand layers are `LOCKED_BY_USER` or `LOCKED_BY_APPROVAL`. I solve around locks; where the repair genuinely depends on a locked layer I will report the exact dependency and the minimum unlock required rather than editing it.
2. **Keep the structural edit locked.** No re-cut. This is a design-system repair inside the approved structure, so timing assumptions stay valid except where a mechanism change alters holds.
3. **Mechanism re-divergence (MG-01/MG3-08).** Produce three materially different directions for the core explanatory beat — at minimum one persistent-object state-change treatment, one spatial/full-frame reveal, one type-led treatment with no panel at all. Different mechanism and composition, not recolored cards.
4. **Author the system, not the scene.** Define one grid with deliberate asymmetry and off-center anchors; a scale ladder with real contrast (display / statement / label / micro); one shape-and-path motif derived from the brief's subject; a value/contrast relationship that separates graphic from footage without a panel; and a rule for when a container is allowed at all — ideally rarely, and then earned.
5. **Typography pass (MG3-06).** Assign explicit roles, re-break lines for grouping and meaning, and set emphasis logic so one idea per scene is loud. Preflight glyphs again after any type change.
6. **Fit-for-purpose references (MG3-05)** only where they can change a decision: vertical explainer mechanisms, extracting principle and derivative risk, never surface.
7. **Gate before full render.** Inspect opening, peak explanatory and resolved states statically, plus one short animated prototype proving the motion language. If it still reads as presentation UI, repair again before spending a full render.
8. **Motion re-justification (MG3-09).** Each surviving animated element gets job, represented change, viewer inference, timing/hold, removal criterion, judged as combined attention load.
9. **Overlay ledger** re-verified, then technical QC, then craft QC re-observed at phone size.
