# Agent Architect v1.1 Round 1 — Infrastructure Evidence

Date: 2026-08-14
Branch: `agent/architect-external-benchmark-2026-08`
Decision: **AGENT ARCHITECT BENCHMARK: REVISE**

## What was actually tested

This step validated the behavioral-evaluation infrastructure itself. It did **not** count the reference smoke adapter as Agent Architect behavior.

## Root-cause gap found

The first `runner.py` implementation could invoke only one candidate call per fixture/trial. That made it structurally incapable of directly orchestrating several release-critical families:

- B1 requires multiple isolated sessions with persistent state between them;
- B2 requires interruption and resume in a fresh/reset session without the original transcript;
- B6 requires a poisoning attempt followed by a later fresh-session behavior probe;
- B8 benefits from the same task executed under different explicit capability profiles.

This was an evaluation-infrastructure defect, not a candidate behavioral failure. Leaving it in place could have encouraged adapters to hide multi-session behavior inside one opaque invocation, weakening independent observability.

## Repair

`architect/evaluation/harness/runner.py` was upgraded to protocol v2 with:

- ordered multi-step fixtures;
- explicit `session_id` and `reset_session` semantics;
- one shared trial workspace across separate step invocations;
- per-step capability-profile overrides;
- mandatory candidate SHA identity check on every step;
- nested structured-result grading;
- independent workspace artifact existence/JSON-value checks;
- distinct exit codes for execution error vs mechanical failure.

`candidate-adapter-contract.md` was updated so a real runtime adapter must preserve actual session/state semantics rather than synthesizing traces after the answer.

## Mechanical smoke test

A deliberately non-release `reference_adapter.py` and frozen smoke fixture/manifest were added solely to test harness mechanics.

The smoke workflow executed two trials and mechanically required both to pass. This demonstrates that the harness can execute, hash-lock its fixture, grade structured observations, persist run evidence, and fail CI if the mechanical invariant fails.

## What this does NOT prove

It does not prove B1–B10 and must not be cited as Agent Architect behavioral PASS. The smoke adapter has no model and intentionally returns a known marker. It exists to prove the measuring instrument functions, not that the subject passes the measurement.

## Remaining release blocker

Round 1 now needs a **real candidate adapter** that:

1. loads the frozen Agent Architect candidate SHA;
2. executes the real `architect/SKILL.md` in a model/runtime;
3. provides truly isolated sessions plus inspectable persistence;
4. exposes controlled tool fixtures and independent side-effect ledgers;
5. enforces capability removal for B8;
6. captures actual resource/tool/state transitions;
7. cannot read hidden grader keys or sealed attack variants.

It also needs sealed/independent B1–B10 fixtures. Candidate-authored public examples may be used for development regression only, not as the sole release holdout.

## Release decision

The measuring infrastructure has moved from narrative specification to executable smoke-proven harness, but the Agent Architect candidate itself has not yet been run through valid held-out B1–B10 trials.

Therefore status remains:

`AGENT ARCHITECT BENCHMARK: REVISE`.
