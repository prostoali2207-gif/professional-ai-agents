## Scope

This round attempted to move PR #1 from architecture/documentation repair to behavioral validation under `v1.1-benchmark-validation-gate.md`. No applied professional agent was created.

The first validation step was release-evidence preflight: determine whether B1–B10 can be executed in a way that would make a PASS claim falsifiable, repeatable, held-out, and independently gradeable.

## Preflight finding

The original gate named the correct behavioral families but was not yet an executable release protocol. It did not freeze test fixtures/versions before observation, assign criticality per family, define a minimum repeated-trial threshold, require mechanical inspection of persistent/side-effect state, distinguish diagnostic self-evaluation from independent release evidence, or specify what happens when a claimed capability cannot be exercised in the validation runtime.

That is a root-cause release-integrity gap: an evaluator could have produced a persuasive narrative over B1–B10 and called it PASS without demonstrating the state transitions, side effects, held-out independence, or reliability distribution that the benchmark itself requires.

The gate was therefore repaired before accepting any release result. A later readiness pass made the missing execution-layer requirement explicit in `behavioral-validation-harness.md`: critical behavioral claims require a runnable environment that exposes the claimed state/actions, not merely a good test description.

## Root-cause repair made in this round

`architect/evaluation/v1.1-benchmark-validation-gate.md` now requires:

1. a pre-registered run manifest with candidate SHA, fixture hashes, grader version, trial count, thresholds, capability profile and evaluator class;
2. explicit P0/P1 criticality for B1–B10;
3. mechanical state/side-effect inspection where the claim is about memory, checkpointing, idempotency, resource loading or downstream state;
4. at least five B9 trials, with the default threshold frozen before execution;
5. held-out security variants and useful-task completion, not refusal-only safety;
6. a rule that self-grading is diagnostic only and cannot solely release a P0/P1 family;
7. a rule that `NOT EXECUTABLE` blocks release unless the benchmark claim is narrowed;
8. repair -> regression -> fresh held-out variant -> coupled-critical-family rerun after failures;
9. conformance with `behavioral-validation-harness.md` so the test environment itself can expose and grade the construct being claimed.

## Why this round is not PASS

A behavioral benchmark is evidence about behavior, not about whether the candidate can describe the desired behavior. The current run cannot honestly establish B1–B6 or B8–B10 under the repaired evidence standard. B7 has only incidental diagnostic evidence. Declaring PASS would therefore reproduce the exact documentation-equals-capability error that v1.1 is intended to eliminate.

## Required next validation round

Round 1 must be run against the repaired candidate using sealed fixtures and an evaluator/runner that can provide:

- isolated sessions and inspectable persistent state;
- transcript-free checkpoint resume;
- controlled tool responses and ambiguous non-idempotent writes;
- instrumented capability/resource loading;
- capability removal/degradation;
- multiple hidden prompt-injection and memory-poisoning variants;
- at least five equivalent independent interactive trials;
- mechanical graders for state, duplicate side effects, resource loads and end states;
- an independent or sealed-key grader for competence inference.

The run manifest and thresholds must be committed or otherwise immutably recorded before candidate outputs are observed.

## Red-team of the validation architecture

A senior agent engineer would reject a PASS based on narrative examples because stateful and tool-semantic claims need environment evidence. An assessment specialist would reject cases authored and graded by the same candidate because construct validity and leakage are uncontrolled. A hiring evaluator would reject a best-run demonstration because it says little about reliability under repeated real work.

The repaired gate and harness contract close these immediate holes. They do not manufacture missing behavioral evidence; that evidence still has to be produced in a controlled runner.
