## Release claims

### Claim A — Operational Product UX / Interaction Design Core

The candidate can convert an evidence-backed operational task into an implementation-ready interaction contract that supports repeated work, complex forms, data-heavy tables, bulk/exception operations, consequential actions, state/recovery, mobile, accessibility and RTL without inventing domain rules or silently taking visual/engineering authority.

### Claim B — Product Interface / Design Systems Core

The candidate can convert an approved interaction contract into a coherent operational product interface system with strong hierarchy, appropriate density, typography, semantic color/state, spacing, tokens, component consistency, responsive/RTL behavior and rendered critique without changing approved product behavior or mistaking generic polish for professional quality.

No claim includes frontend implementation competence or independent final self-approval.

## Evaluation principles

- Freeze professional construct before held-out authoring.
- Development fixtures and held-out fixtures are separate.
- Rendered claims require rendered artifacts.
- Critical failures cannot be averaged away.
- External/local historical PASS does not transfer.
- FleetDesk is not the only practical fixture and must not define the reusable core.
- Do not reopen generic qualification infrastructure merely to execute this plan.

## Stage D — grader calibration

Judgment-heavy criteria require calibrated comparative grading.

Calibration set:
- clear expert PASS;
- clear expert FAIL;
- difficult boundary pairs;
- intentionally polished but task-weak output;
- intentionally dense but professionally appropriate output;
- familiar standard UI vs unnecessary novelty;
- visually distinctive but contract-breaking output.

Calibrate disagreement per criterion. Do not rely on one unvalidated scalar score.

If calibrated professional judgment cannot be obtained for a subjective criterion, narrow the release claim rather than pretending certainty.

## Stage E — rendered practical qualification

Mandatory. Semantic PASS is not final qualification.

### Practical P1 — data-heavy operational workspace
Must include:
- dense table/list;
- retrieval controls;
- selection/bulk behavior;
- loading/empty/error state;
- primary-detail or equivalent context preservation.

Evidence:
- actual narrow + desktop renders;
- interaction trace;
- UX contract;
- interface/design-system contract;
- independent review.

### Practical P2 — consequential workflow
Must include:
- money, availability, destructive or similarly consequential state;
- review/confirmation proportional to risk;
- cancel/back/recovery;
- clear amount/scope/consequence.

### Practical P3 — form and recovery
Must include:
- conditional/alternative fields;
- validation;
- server/network failure;
- preserved valid input;
- accessible error recovery.

### Practical P4 — mobile + RTL
Must include:
- approx 390px narrow viewport;
- Arabic RTL;
- mixed LTR IDs/numbers;
- task completion without horizontal page scroll;
- visible focus/touch behavior where applicable.

### Practical P5 — cross-screen design-system audit
Provide several screens with deliberate drift:
- parallel palettes;
- inconsistent buttons;
- arbitrary spacing/radius;
- duplicate status colors;
- one-off table styles.

Candidate must:
- diagnose root system;
- distinguish justified exception from drift;
- produce bounded consolidation;
- avoid unrelated redesign;
- re-observe corrected render.

## Stop-loss execution record

Before every provider/model-assisted qualification stage record:
- frozen candidate/cycle;
- stage and execution-chain identity;
- prior technical failure classes;
- whether bounded repair has been consumed;
- run authorization class;
- expected professional information gain;
- maximum allowed repair/retry under issue #129.

Technical defect handling:
`classify -> at most one bounded repair if authorized -> regression -> one eligible retry -> STOP on another technical defect in same chain`.

If STOP fires: preserve evidence and return `NOT_EXECUTABLE`.

1. deterministic preflight PASS;

4. all mandatory rendered practicals PASS;
5. independent reviewer gate PASS;
