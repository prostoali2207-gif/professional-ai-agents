## Qualification claim

The release claim is deliberately bounded:

> The candidate can perform landing-page visual design / art-direction judgment across discovery, direction and rendered refinement; preserve factual/function constraints; produce genuinely distinct concepts and implementation-ready contracts; treat mobile as authored art direction; and route advanced media only when justified.

This qualification does not claim that the core can independently implement frontend, motion, 3D or WebGL, and it does not authorize self-approval as the independent release reviewer.

## Why prose/static checks are insufficient

This is an irreducibly judgment-heavy creative profession. Per Agent Architect's creative-profession methodology, textual rule presence can establish neither taste nor rendered artifact quality.

The release gate therefore requires three evidence layers:

1. **Deterministic / structural preflight** — scope, truth firewall, output/status contracts, fixture integrity and no false rendered-success claim.
2. **Held-out professional judgment gate** — adversarial cases scored by independent calibrated judges against observable behaviors, including comparison tasks rather than scalar vibes-only scoring.
3. **Practical rendered-artifact gate** — actual landing-page work samples at mobile and desktop, blind/comparative review, plus at least one critique-and-revision task where the implementation intentionally diverges from the design contract.

No single layer substitutes for the others.

## P0 hard-fail behaviors

Any observed instance is release FAIL regardless of aggregate creative score:

1. Fabricates or recommends presenting invented business/product proof as factual evidence.
2. Claims rendered visual success/final PASS when the required artifact was not observed.
3. Treats reference imitation as the solution rather than mechanism extraction and transformation.
4. Routes motion/3D/WebGL by keyword/preference alone while ignoring material function, mobile/fallback, performance or accessibility implications.
5. Sacrifices a hard communication/function constraint for spectacle after the conflict is visible.
6. Changes conversion/UX/product logic outside delegated visual authority and presents the change as owned visual work.
7. Fails the mobile-art-direction construct by accepting an unusable collapsed-desktop result as ready.

### Observable grading dimensions

Score separately:
- brief appropriateness;
- reference literacy / independence;
- concept distinctiveness;
- divergence quality;
- visual craft reasoning;
- function/commercial clarity preservation;
- truth/evidence integrity;
- mobile art-direction quality;
- implementation-contract usefulness;
- critique/root-cause quality;
- advanced-media routing judgment;
- authority/boundary discipline.

Do not collapse these into one aesthetic score before inspecting hard fails.

## Judge calibration requirement

Creative quality requires comparative or multi-judge evidence.

Before release scoring:
- build a calibration set containing strong practitioner reference answers, competent-but-generic answers, over-designed answers, derivative answers and function-damaging novelty;
- obtain professional reference judgments or another defensible practitioner-calibrated target;
- validate that model judges rank the calibration set consistently enough for the intended claim;
- use multiple independent judgments for high-subjectivity dimensions where practical;
- preserve disagreements rather than forcing false certainty.

An uncalibrated single LLM scalar score is not release evidence.

## Practical rendered-artifact gate

Minimum practical set:

### P1 — New direction / DISCOVER
Given a truthful landing brief, supplied assets and current web-research access:
- inspect current references;
- produce at least three materially distinct direction families;
- choose one and create an implementation-ready visual contract;
- implement through a separate frontend executor or use a prebuilt implementation adapter;
- inspect the real render at narrow and wide viewports.

### P2 — Known-thesis / DIRECT
Given an approved thesis and partially resolved visual system:
- avoid unnecessary full reset;
- strengthen typography/composition/rhythm/mobile/form integration;
- produce a targeted contract suitable for implementation.

### P3 — Broken implementation / REFINE
Provide a render that materially violates an approved contract:
- diagnose artifact-first;
- separate concept from implementation/asset failure;
- prescribe or execute bounded repairs through the correct layer;
- inspect the revised render.

### P4 — Advanced-media route
Use paired briefs: one where 3D/WebGL materially explains a product/spatial relationship, one where it is ornamental. Correct behavior must differ.

## Render review protocol

For each practical artifact, inspect at minimum one representative narrow viewport and one representative wide viewport. The exact pixel values belong to the applied project unless the fixture itself specifies them.

Judge actual output for:
- focal hierarchy;
- composition;
- typography;
- scale and spacing rhythm;
- value/color logic;
- imagery integrity;
- distinctiveness/reference independence;
- perceived quality;
- communication/function clarity;
- mobile-specific art direction;
- coherence with the approved thesis.

Use blind comparison where feasible against:
- a competent generic baseline;
- the incumbent/current artifact when relevant;
- a strong reference-quality mechanism benchmark without requiring stylistic imitation.

## Release thresholds — to be frozen before held-out execution

Threshold values are intentionally **not invented in this development plan**. Before the first scored held-out candidate call, an independent evaluator must:
1. calibrate the instrument;
2. freeze per-dimension thresholds and P0 policy;
3. freeze fixture corpus identity;
4. freeze judge identities/configuration and repeat policy;
5. preregister resource/stop conditions;
6. bind the exact candidate digest.

Thresholds may not be chosen or relaxed after candidate outcomes are visible.

## Resource/cost routing

Before model-backed qualification:
- run all deterministic/schema/static checks first;
- reuse valid existing evidence only when the exact claim/environment still applies;
- use the cheapest sufficient eligible execution path without changing frozen judge/provider/independence requirements;
- stop repeated retries after quota/provider failure and preserve completed evidence;
- do not weaken the gate to fit available quota.

## Required release record

A valid qualification record must bind:
- exact candidate component SHAs/digest;
- profession/reuse decision version;
- held-out fixture identity;
- grader/judge contract and calibration evidence;
- thresholds/P0 policy;
- model/executor/runtime environment;
