# Learning Coach — evaluation plan v0.1

Status: PRE-SKILL PLAN
Date: 2026-09-23

## Claim boundary

Candidate claim: the capability can sequence skill-acquisition coaching for low-risk cognitive/procedural skills, using a domain task model supplied by a relevant domain skill/source, while adapting support to observed learner performance.

This is not a claim of universal pedagogy expertise, subject-matter expertise, clinical/educational diagnosis, T1 qualification, or expert validation.

## Critical claims

### LC-C1 — True-beginner sequencing
A self-declared true beginner receives a minimum viable task model and tiny modeled example **before** the first assessed/guided attempt unless an uninstructed baseline is explicitly justified.

Hard fail: first move is "try it" with no usable orientation/model.

### LC-C2 — Learner does cognitive work
The coach does not complete the authentic task for the learner by default when acquisition is the goal.

Hard fail: full solution replaces the learner attempt before any meaningful practice.

### LC-C3 — Targeted feedback
Feedback identifies the dominant observable bottleneck and gives a decision rule + retry.

Hard fail: generic praise, personality judgment, or a long list of unrelated corrections.

### LC-C4 — Fading
Support is reduced after repeated representative success.

Hard fail: permanent hints/modeling despite demonstrated competence.

### LC-C5 — Domain boundary
The generic coach consumes domain rules rather than inventing them.

Hard fail: creates domain-specific doctrine/standards from generic pedagogy.

### LC-C6 — Anti-template adaptation
The instructional response changes when learner state/task structure changes.

Hard fail: mechanically repeats the same lesson structure despite contradictory evidence.

### LC-C7 — Transfer/retrieval
Mastery is checked by independent performance, retrieval, discrimination, or transfer—not self-report/recognition alone.

## Evaluation families

1. cold-start first contact;
2. novice with existing task model;
3. learner makes one repeated error;
4. learner succeeds repeatedly and support should fade;
5. user requests full answer while also claiming learning goal;
6. domain skill imposes a fidelity/safety rule;
7. new context requires transfer;
8. ambiguous evidence / insufficient sample;
9. anti-template pair: two learners same topic, different bottlenecks.

## Grading

Prefer deterministic ordering checks where possible:
- presence/order of orient/model/attempt;
- whether learner action is required;
- number of active correction targets;
- whether next attempt exists;
- whether domain rule provenance is explicit.

Judgment-heavy fit/adaptation requires independent review for T1.

## Release status

Author-side static/development checks may support project-use candidate status only.
T1 requires independent held-out practical evaluation.
