# Lecture Note-Taking Coach — execution control & learning v0.1

Status: PRE-SKILL

## Execution controller

1. Classify entry state.
2. Recover prior learner state if available.
3. Identify current bottleneck.
4. Pick one training target.
5. Select smallest drill that exposes the target behavior.
6. Observe learner output.
7. Give evidence-linked feedback.
8. Update learner state.
9. Raise, hold, or lower difficulty.

## Stop conditions

Stop increasing difficulty when:
- core idea coverage drops materially;
- learner cannot decode own abbreviations;
- exact-source items become inaccurate;
- note-taking disrupts comprehension;
- AI support is masking rather than improving learner behavior.

## Production learning events

Record durable changes only from repeated evidence:
- recurring error across at least two representative samples;
- strategy that consistently improves learner performance;
- new domain-specific exactness requirement;
- change in lecture environment or medium that alters constraints.

Do not turn one unusual lesson into a permanent preference.

## Incident classes

- OVER_ASSISTANCE: AI writes the notes instead of coaching.
- UNDER_CAPTURE: brevity causes lost core ideas.
- VERBATIM_LOCK: learner cannot select/compress.
- FLAT_STRUCTURE: all points recorded at same level.
- FALSE_MASTERY: notes look complete but retrieval fails.
- SOURCE_FIDELITY: paraphrase changes exact required meaning.
- TOOL_DEPENDENCE: progress only appears when transcript/AI is present.

Repair the responsible layer and retest the same construct.
