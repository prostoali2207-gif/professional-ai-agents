# Hypertrophy Training — execution control and production learning v0.1

Status: PRE-SKILL

## Decision run record

For every material programming change preserve:
- state/version used;
- material observations and unknowns;
- decision/action;
- variables intentionally held constant;
- expected effect;
- verification criterion;
- escalation/boundary state;
- next review point;
- outcome classification: SUPPORTED / NOT_SUPPORTED / UNRESOLVED / SUPERSEDED.

Do not preserve private chain-of-thought. Preserve observable evidence and professional rationale sufficient for replay/review.

## Remediation loop

On a bad decision or practical-eval failure:

`failure -> minimal reproducible history -> classify root-cause layer -> repair responsible layer -> add regression -> nearby/adversarial retest -> practical retest if material`.

Responsible layers:
- evidence/source;
- professional invariant/judgment;
- decision procedure;
- state/comparability;
- routing/context availability;
- safety/authority;
- evaluator/grader;
- runtime/infrastructure.

Do not patch the final SKILL with fixture wording when the responsible layer is evidence, procedure, state or evaluation.

## Execution stop conditions

Stop or narrow the programming decision when:
- safety/clinical authority is triggered;
- a decisive input is unavailable;
- recent history is materially non-comparable;
- current evidence is contested/version-sensitive and retrieval is unavailable;
- the requested action exceeds validated healthy-adult scope.

## Training-data feedback loop

After each session:
1. log actual sets separately from plan;
2. flag material technique/ROM/equipment changes;
3. classify symptom boundary;
4. record only future-useful readiness/recovery context;
5. update decision verification status.

After each microcycle/block:
1. compare priority outcomes and target-muscle progression;
2. inspect accumulation of fatigue and adherence;
3. evaluate whether prior intervention changed trajectory;
4. preserve supported reusable local facts (e.g. tolerated setup/dose) with provenance;
5. mark unsupported hypotheses as such rather than converting them into permanent rules.

## Production incident classes

Capture:
- overprescribed volume;
- underdosed effort/volume;
- false plateau;
- false progression due technique/equipment drift;
- failure-induced recovery interference;
- poor exercise substitution;
- invalid RIR assumption;
- missed symptom escalation;
- stale state/supersession failure;
- logging/instruction injection;
- unexplained repeated user correction.

## Promotion rule

A single user's successful block does not become universal scientific knowledge.

Promote a lesson only to:
- user/project state when it is a reproducible individual response;
- procedural guidance when repeated cases and evidence support the mechanism;
- stable core only when authoritative evidence and representative evals justify generalization.

## Drift triggers

Re-review evidence/package when:
- ACSM or another authoritative body supersedes the 2026 position stand;
- a major meta-analysis materially changes volume/failure/ROM/deload conclusions;
- repeated production incidents cluster around one decision policy;
- state/logging schema repeatedly fails to preserve comparability;
- special-population use becomes a product requirement.

## Authority

Production feedback may refine programming for the same trainee. It may not expand the skill into clinical diagnosis, rehabilitation, special-population treatment or nutrition/medication authority without a new architecture/evidence/qualification cycle.
